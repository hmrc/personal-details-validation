{panel:title=Description|borderStyle=dashed|borderColor=#cccccc|titleBGColor=#ececec|bgColor=#ffffff}
Following the spike on VER-7213 PDV currently tracks failed attempts only against the authenticated CredID. This creates two gaps:
 * a user can use different CredIDs to obtain more attempts against the same NINO
 * some journeys including DWP can enter PDV without a CredID, so no CredID retry state is recorded.

Introduce a separate NINO retry lock alongside the existing CredID retry mechanism.

The two controls have different purposes:
 * *NINO state* decides whether PDV is allowed to check that NINO. It is shared across all CredIDs.
 * *CredID state* remains the source of the attempt number and decides which failure or lockout page the user sees.

A NINO must be locked for 24 hours after its third failed direct NINO validation. Submitting an already locked NINO must not reveal that the NINO is locked where a CredID exists, the user must continue through the normal CredID failure-page sequence.

{panel:title=Required behaviour|borderStyle=dashed|borderColor=#cccccc|titleBGColor=#ececec|bgColor=#ffffff}
 # For every completed failed direct-NINO validation:
 ## increment the failure count for the entered NINO
 ## increment the submitting CredID count when a CredID exists
 ## exclude technical/infrastructure failures from both counts
 # Lock the NINO when its third failed validation is recorded.
 # Keep the NINO locked for 24 hours from the third failure.
 # Check a direct NINO before calling Authenticator or Citizen Details.
 # When the NINO is already locked:
 ## make no Authenticator or Citizen Details call
 ## do not increment the NINO count or extend its lock
 ## increment the submitting CredID count when one exists
 ## return the ordinary failed-validation response for that CredID attempt.
 # Continue to use the CredID count to select the page:
 ## CredID attempt 1: first incorrect-details page, with 2 attempts remaining
 ## CredID attempt 2: final-attempt page, with 1 attempt remaining
 ## CredID attempt 3: existing lockout page or caller {{failureUrl}}
 # Keep the existing journey entry behaviour for an already locked CredID.
 # A successful direct NINO validation below the threshold (3) must clear both the below threshold NINO failures and that CredID's retry state.
 # A blocked submission must not clear an active NINO lock.
 # Treat {{lockedUntil}} as the authoritative expiry time. Mongo TTL is for eventual cleanup only.
 # If the NINO lock store cannot be read, fail closed through the technical failure route and do not call Authenticator.{panel}

case class NinoLock(
  ninoKey: String,
  failedAttempts: Int,
  firstFailedAt: LocalDateTime,
  lastFailedAt: LocalDateTime,
  lockedAt: Option[LocalDateTime],
  lockedUntil: Option[LocalDateTime],

Where ninoKey is a normalised NINO to avoid potential exploits like removing a suffix or placing spaces. I think we should strip the spaces, make it uppercase and remove the suffix if one exists for normalisation. {panel:title=Acceptance criteria|borderStyle=dashed|borderColor=#cccccc|titleBGColor=#ececec|bgColor=#ffffff}
 # Implement the tasks from above
 # Ensure a direct NINO is locked after 3 completed failed validations within the configured window.
 # The lock lasts exactly 24 hours from the third failure and is evaluated from {{{}lockedUntil{}}}, independently of Mongo TTL cleanup.
 # Every ordinary failed direct NINO validation increments NINO state and when present CredID state.
 # An actively locked direct NINO makes no Authenticator or Citizen Details call.
 # Submitting an already locked NINO increments only the submitting CredID count and does not extend the NINO lock.
 # CredID attempt 1, 2 and 3 continue to produce the existing first failure, final attempt and lockout/{{{}failureUrl{}}} outcomes.
 # A new CredID receives its own independent three attempt page progression against an already-locked NINO.
 # Existing journey entry lockout behaviour for a locked CredID is unchanged.
 # A successful validation below the threshold clears below threshold NINO state and CredID retry state.
 # A locked NINO submitted without a CredID makes no downstream details-checking call and uses the same non-disclosing outcome as an ordinary no-CredID failure.
 # Lock store and Auth failures fail closed and do not appear as zero attempts/no CredID.
 # Atomic updates prevent lost NINO or CredID increments. (such as $inc)
 # The NINO key uses the same suffix/equivalence normalisation as Authenticator.
 # Retry limits fallbacks, content and README documentation consistently state 3 attempts and a 24-hour lock{panel}
